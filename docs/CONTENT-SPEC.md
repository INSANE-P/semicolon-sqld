# 내용 파일 규격

`content/` 아래 파일 하나가 장 하나다. 파일은 `SQLD.add({...})` 를 한 번 부른다.
빌드가 없고 `file://` 로도 열려야 해서, ES 모듈이나 fetch 를 쓰지 않는 평범한 스크립트다.

본보기는 `content/m9.js` 다. 새 장을 쓸 때 이 파일의 모양과 말투를 그대로 따른다.

## 장

```js
SQLD.add({
  id: 'm9',                 // 파일 이름과 같다
  title: 'NULL 속성의 이해',
  minutes: 12,              // 읽는 데 걸리는 시간(분)
  weight: 3,                // 출제 비중 1(가끔) 2(자주) 3(거의 매회)
  lead: '한두 문장. 이 장이 왜 점수가 되는지.',
  goals: ['이 장을 읽고 나면 할 수 있어야 하는 것', '…', '…'],   // 3~4개
  blocks: [ … ],            // 본문
  keys: ['시험 직전에 볼 한 줄 암기', …],                        // 4~8개. 한 장 요약에 모인다
  cards: [{ q: '앞면 질문', a: '뒷면 답' }, …],                 // 4~8개
  quiz: [ … ]               // 문제
});
```

## 글자 표기

글자 칸(p, 목록, 표 칸, 문제, 보기, 해설, 카드)은 HTML 이 아니다. 화면에 낼 때 전부 이스케이프하므로
`<`, `>`, `&` 를 그대로 써도 된다. 아래 네 가지만 꾸밈으로 바뀐다.

- `` `코드` `` → 고정폭 글자
- `**굵게**`
- `==형광펜==` (정말 외워야 하는 낱말에만, 한 문단에 한 번 정도)
- 줄바꿈 `\n`

SQL 은 백틱 템플릿 문자열로 쓰고 들여쓰기는 공백 2칸, 예약어는 대문자다.

## 본문 블록

```js
{ t: 'h',  x: '소제목' }
{ t: 'p',  x: '문단' }
{ t: 'ul', items: ['…', '…'] }
{ t: 'ol', items: ['…', '…'] }
{ t: 'table', head: ['구분', '뜻'], rows: [['…', '…']], caption: '선택' }
{ t: 'data', name: 'EMP', head: ['ENAME', 'SAL'], rows: [['KIM', 100], ['LEE', null]] }   // 예시 테이블. null 은 NULL 로 보인다
{ t: 'sql', code: `SELECT …`, result: { head: ['A'], rows: [[1]] }, note: '결과에 붙이는 한 줄(선택)' }   // result, note 는 선택
{ t: 'trap', title: '함정 이름', x: '시험이 어떻게 속이는지와 가르는 규칙' }
{ t: 'tip',  title: '이렇게 외워요', x: '…' }
{ t: 'vs', a: { title: 'RANK', items: ['…'] }, b: { title: 'DENSE_RANK', items: ['…'] } }   // 헷갈리는 둘 나란히. c 까지 가능
{ t: 'fig', svg: `<svg viewBox="0 0 640 240" …>…</svg>`, caption: '그림 설명' }
{ t: 'check', q: '읽다가 스스로 답해 볼 질문', a: '눌러야 보이는 답' }
```

### 그림(fig)

- 직접 그린 SVG 만 쓴다. 교재 그림을 옮기지 않는다.
- `viewBox` 폭은 640, `width`/`height` 속성은 쓰지 않는다.
- 색은 클래스로만 준다(밝은 화면과 어두운 화면에서 같이 바뀐다). 색 코드를 직접 쓰지 않는다.
  - 선: `class="ln"`(기본 선) `ln-a`(강조 선) `ln-r`(빨간 선) `ln-d`(점선)
  - 면: `class="bx"`(옅은 상자) `bx-a`(강조 상자) `bx-r`(빨간 상자) `bx-y`(형광 상자)
  - 글자: `class="tx"`(기본) `tx-s`(작고 흐린) `tx-b`(굵게) `tx-a`(강조색) `tx-r`(빨강) `tx-m`(고정폭)
- 글자는 `text-anchor="middle"` 로 상자 가운데에 두고, 한글 한 글자를 14px 정도로 보고 상자 밖으로 넘치지 않게 한다.
- 화살표는 `marker-end="url(#arr)"` 를 쓴다(`#arr`, `#arr-a`, `#arr-r` 가 페이지에 이미 있다).
- 그림은 글로 풀면 길어지는 것(구조, 흐름, 범위, 방향)에만 쓴다. 장마다 1~3개.

## 문제

```js
{
  id: 'm9-01',                       // 장 id + 두 자리 번호
  level: 2,                          // 1 기본 2 실전 3 고난도
  q: '문제 문장',
  tables: [{ name: 'T', head: ['A', 'B'], rows: [[1, null]] }],   // 선택
  code: `SELECT …`,                  // 선택
  choices: ['…', '…', '…', '…'],     // 반드시 4개. SQL 보기는 { code: `…` }, 결과 표 보기는 { head: […], rows: [[…]] }
  answer: 2,                         // 1~4
  why: '해설. 정답 근거와, 틀린 보기가 왜 틀렸는지까지.',
  tag: '집계와 NULL'                  // 그 장 안의 세부 주제
}
```

- 정답 번호가 한쪽으로 몰리지 않게 1~4 를 고르게 쓴다.
- 결과를 묻는 문제는 예시 테이블을 작게(3~8행) 직접 만들고, 한 줄씩 손으로 따라가 답을 검산한다.
- Oracle 기준으로 쓴다. SQL Server 와 다른 점을 묻는 문제는 문제 문장에 DBMS 를 밝힌다.
- 답이 둘로 읽힐 수 있는 문제는 만들지 않는다. 헷갈리게 하되 근거는 하나여야 한다.
- 교재 문제를 옮기지 않는다. 같은 개념과 함정을 새 테이블과 새 숫자로 묻는다.

## 말투

- 해요체. 친구가 옆에서 풀어 주듯 쓴다. 정의를 먼저 던지지 말고, 무슨 상황에서 왜 필요한지부터.
- 한 문단은 서너 문장 안쪽. 시험에 안 나오는 이야기는 쓰지 않는다.
- 꾸밈말, 표어, 이모지, 느낌표를 쓰지 않는다. "핵심은", "중요한 것은", "결론적으로" 같은 머리말도 쓰지 않는다.
- 용어는 처음 나올 때 한 번 풀어 준다. 예: 카디널리티(한쪽 한 건에 반대쪽이 몇 건 붙는지).
- 시험이 묻는 방식 그대로 적는다. 예: "틀린 것을 고르라는 문제에서 보기로 자주 나와요."
